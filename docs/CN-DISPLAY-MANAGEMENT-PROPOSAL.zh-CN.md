# 仪表与 HUD 显示焦点协议（提案与离线原型）

建议采用“应用声明能力 + 显示服务仲裁 + 商店统一设置”的结构。
当前已有可操作的离线原型 `experiments/display-focus/demo.html` 和确定性测试；
尚未安装车机调度服务，也没有改动任何已发布应用的显示控制。

## 成熟方案与边界

借鉴 Android Automotive Audio Focus 的申请、拒绝、短暂失焦及恢复机制：
https://source.android.com/docs/automotive/audio/audio-focus
它是音频焦点协议，不能直接拿来控制 MGU 仪表；本提案沿用生命周期，
将音频混音关系换成显示区域兼容矩阵。不是宣称 MGU 已有这样的标准。

底层继续使用 cluster-render 的图层合成、原厂告警让位、slot 管理和映射保护。
商店只保存用户选择并展示状态，关闭商店不会影响调度。第一版仲裁应放在
cluster-render 服务内或其受控的常驻伴随服务中，不能仅在商店前端执行互斥。

## 接口与职责

安装清单声明协议版本、逻辑区域和角色（主内容、附加信息）。安装器校验并
登记应用身份；连接端使用进程凭据绑定身份，不信任应用自报名称或优先级。
应用按自己已声明的区域申请、释放、续租并接收授权/失焦事件。
用户通过商店选择主应用、查看暂停原因和恢复原厂；应用不能调用管理接口。

申请包含 requestId；授权包含 session + lease 代次。断线重连必须重新申请，
旧授权不能续用。服务以单调时间管理租约（试验：6 秒），应用每 2 秒续租。
图层绑定授权；未经授权的写入由服务拒绝，而不是仅要求应用自觉隐藏。

切换顺序：撤销旧写入权限 → 服务隐藏旧图层 → 渲染器确认 → 授权新应用。
确认携带切换 epoch，防止迟到回执误释放新授权。超时显示“释放超时”，
不在未确认的旧画面上再授权新应用。原厂安全告警具有服务固定的最高优先级，
用户和应用都不能改变；告警消失后仅恢复用户仍然选择且在线的应用。

## 区域和兼容

逻辑区域不能直接等同物理 target：map/panel 可能在仪表屏幕上互相覆盖，
所以第一阶段将仪表主内容作为一个互斥区域，HUD 另一个区域。
先覆盖 Cluster Metrics 与 Cluster Themes，再逐项接入 Waze、Redline。
附加信息不能默认都允许叠加；后续按主题布局、车型、渲染能力维护经过验证的
区域兼容矩阵。原厂告警不进入可配置矩阵。

现有 HudClaim 位于 `/dev/shm/mgu-hud`，有 2 秒刷新、6 秒过期机制。
主题和 Redline 已使用它；迁移时由一个适配器读取旧占用，保守地标成
“未纳管应用占用”，阻止新应用抢占。不能让新旧两套机制各自决定归属。
该文件是兼容提示，不能作为可信授权来源。未接入协议的应用不承诺统一控制。

服务重启需先重建实际图层状态并清除失效授权，再恢复经校验的持久选择。
仅凭服务内存清空不能假定车机已恢复原厂。卸载、崩溃、异常包与 socket 洪泛
均需在真正接入时测试。本次原型只验证策略流程，不冒充上述生产保障已完成。

## 本次交付和后续验证

离线页面可选择两个区域的主应用，模拟原厂告警、旧应用占用、释放超时和掉线。
测试覆盖切换顺序、迟到确认、超时不抢占、告警恢复、能力校验、租约过期、
重连和恢复原厂。它不包含车辆网络访问或共享配置修改。

Cluster Metrics 0.6.1 仅作为最新上游的汉化 Beta 发布，不启用上述调度原型。
之后将服务协议与两个应用适配作为独立 Beta 实验，验证告警、导航、熄火唤醒、
崩溃回收和关闭商店后的持续运行，再向上游提交协议/服务、SDK、商店 UI 分开的 PR。
协议与策略使用英文并与 CN 分发、中文翻译解耦，方便上游复用。
