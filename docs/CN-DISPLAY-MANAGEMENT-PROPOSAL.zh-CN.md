# 仪表与 HUD 统一管理建议

本次只发布 Cluster Metrics Beta；以下为后续设计，不代表已经实现。

## 现状

cluster-render 已统一接收各应用图层，按 ambient/content/overlay/alert 与 z
排序；exclusive 隐藏下层，visible 控制释放，contend 控制是否重试占位。
原厂告警、导航和显示服务不可用由现有仲裁和保护机制处理。
但服务不知道“温度卡片和主题的转速表在视觉上重叠”，也没有统一的用户选择页面。
各应用自己写设置或开启显示，无法保证跨应用布局不冲突。

## 建议产品

在商店新增“仪表与抬头显示”页面，每个区域单独选择：

- 仪表主画面：原厂／地图／仪表主题；主画面只选一个。
- HUD 主内容：原厂导航／手机地图／应用导航；主内容只选一个。
- 附加信息：Cluster Metrics、换挡提示等，只允许已验证能共存的组合。
- 显示当前占用应用、被暂停原因，提供“一键恢复原厂显示”。

原厂安全告警优先级最高，用户不能关闭现有告警让位或映射保护。
切换时先保存选择并请求旧应用隐藏，收到释放确认后启用新应用；
超时保留原来的可用画面或恢复原厂，不形成多个应用反复争抢。

## 实现边界

把显示选择存放在一个由服务管理的策略文件/API；应用只申请能力及区域，
不能通过私改 cluster-render.local.conf 获得优先级。兼容旧客户端的默认行为。
以应用身份、区域、角色、租约和心跳构成申请；应用退出、掉线或卸载自动释放。
区分软件图层的遮挡和 BMW slot 所有权，不用简单 kill 进程模拟互斥。

分阶段：先只读显示占用状态；再做主画面选择及恢复原厂；最后逐项放开
附加信息共存。需要独立 Beta 与车辆验证，不把服务协议改动夹带到新应用移植中。

## 本次 Beta

Cluster Metrics 默认 disabled，HUD 默认导航期间隐藏；完整保留现有服务保护。
用户选择显示位置后开启，以便分别验证仪表、HUD、主题和全屏地图共存。
禁用只控制显示，上游信号采集仍运行；统一租约和集中暂停采集属于后续工作。
