# M Vitals 与 ZF 8HP：CN Beta 集成与验证

这两个应用在中控应用列表中打开。M Vitals 沿用 `car_vitals` 应用 ID，安装新版本会升级现有应用；ZF 8HP 使用 `zf8hp`，已有同 ID 的导出版本可以升级，未安装时作为新应用安装。本次代码未连接车辆、未部署到车机；实车兼容性由 CN Beta 更新后的验证确认。

## 已实现内容

| 应用 | 内容 |
| --- | --- |
| M 车辆仪表 | 发动机、温度、燃油与点火、底盘四页；增压目标/实际、充气量目标/实际成对显示与五分钟历史；胎压单位、无效值及无数据状态延续上游实现。 |
| ZF 8HP 变速箱监测 | 实时、离合器、换挡、自适应图、温度分布、详情、参考七页；保留当前数据、历史、缓存和读取失败状态的区别。 |
| 两者共同 | 固定简体中文；完整 RHMI 页面和设置；默认关闭、可手动开启的演示模式；车内 donor SDK 链接；兼容当前原生渲染服务的连接和重连。 |

M Vitals 的成对增压值使用同一次环境气压值换算为表压。目标值、实际值和环境气压中的缺失值不会被当作零压；只有实际值缺失时保留有效目标值，并清除画面上的实际值。充气量保持百分比，不按压力处理。

ZF 8HP 先读取 EGS 标识 `F150`，按 `0F25D0` 与混动车型 `0F21E0` 的对应布局解释数据。混动型号不支持的记录显示不支持，不发起对应读取；长度不同的记录按对应布局解释或展示原始字节。未匹配型号默认停止后续数据读取；设置中显式选择尝试其他型号后仍校验响应标识与长度。应用只向 EGS 地址 `0x18` 发起 `0x22` 数据读取和 `0x19` 故障读取，不含适应值重置、故障清除、编程或执行器控制。

读取失败不会更新时间戳或把历史值伪装成新数据。应用重启后从快照恢复的数据标记为缓存，缓存中的型号也不会直接授权实时读取；新识别的型号与缓存型号不同会丢弃旧数据。相同型号标识不是车辆唯一身份，因此缓存仍保留明确标记，等待本次读取更新。

## 构建与版本

源码包入口是 `javascript/localized-entry.js`，先加载安装阶段生成的 `javascript/app.js`，再从 `global.__mguLocalizedSdk` 使用 `OnlineApp` 与 `logging`。源码包没有 BMW SDK、`node_modules`、运行日志、车辆快照或设备身份；安装时由本车 donor 生成 SDK 桥。

本次 `car_vitals` 发行号为 `2.27.4`，高于增强基础版本 `2.27.3`。`zf8hp` 为 `1.5.7`，高于导出版本 `1.5.6`。

两应用依赖 `mgu-deploy >= 0.8.18` 和 `mgu-render >= 0.6.21`，发布范围为 ID7。应用自己的完整源码包保存在 `apps/<id>/package/`；旧的 `localized/apps` 导入流程不能覆盖这些增强包。全局发布目录已登记 `zf8hp` 和中文商店文案。

## CN Beta 上车验收

1. 从 CN Beta 更新 M 车辆仪表，安装或更新 ZF 8HP。确认应用和依赖安装成功，记录商店显示的最终版本号。
2. 打开 M 车辆仪表，确认四页、设置和中文正常。燃油与点火页检查目标/实际增压、目标/实际充气量；支持的数据应随工况更新，不支持的数据应显示缺失状态。
3. 打开 ZF 8HP，确认七页均能切换，查看 EGS 型号与连接状态。受支持型号应显示真实读取值；无数据、缓存和不支持提示不能显示为正常实时读数。
4. 退出后重新打开应用，确认画面恢复；恢复的 ZF 数据应先标为缓存，读到新数据后更新。演示模式开启时应始终看到演示标记，验收实时数据时关闭演示模式。
5. 将画面、功能和型号兼容性问题反馈给开发。用户确认 CN Beta 满足需求后，才进入 Stable 发布。
